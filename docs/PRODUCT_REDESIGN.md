## 1. 本次解决什么

让用户无需理解协议或依靠开发者操作，就能完成「部署自己的服务、加入手机和浏览器、选择同步范围、处理通知、处理异常」。三端是同一个产品的三个入口，不要求它们具有相同布局。

不再等所有底层缺陷关闭才开始设计。网络切换长等待仍是重要缺陷，但不阻塞页面结构和正常流程设计。安全问题、数据丢失和当前切片必需的可靠性修复仍优先。

旧 [用户 Alpha 信息架构](PRODUCT_INFORMATION_ARCHITECTURE.md) 保留为历史依据，其中的页面布局和实施顺序不作为本轮默认答案。已确认的安全及业务边界继续保留。

### 保留的产品边界

- Android 决定哪些应用、正文和操作权限可以离开手机，默认空选择，操作默认关闭
- 每台 Android 可在设置中独立选择接收浏览器，成员获批不等于自动接收该手机的通知。这项新需求替代此前向全部已授权浏览器同步的产品约定，生产发送策略已在 Android 实现
- 浏览器展示偏好只影响本机，不冒充手机侧隐私控制
- 成员批准、重命名和撤销由服务端管理端负责，客户端只读展示权威名称
- 通知内容强制 E2EE，服务端管理端不展示正文、回复、头像或操作内容
- 当前通知不是历史归档，工具栏角标表示未查看的新通知，不是活动通知总数
- 操作必须绑定来源手机和当前通知版本，结果不确定时不得显示成功或建议盲目重试
- 浏览器通知的明确主动关闭继续遵循现有清除策略，不确定关闭来源时不删除手机通知
- 管理端与公开中继隔离，重设计不意味着新增公网常驻管理后台
- 不新增公开注册、云账号、历史搜索、文件传输、远程桌面或多管理员体系

## 3. 核心用户路径

### A. 从空环境到第一条通知

```text
部署 Docker 服务 → CLI 初始化 → 按指引启动独立管理端并登录
  → 管理端生成 Android 加入码
  → 手机填写服务地址、加入码、申请名称 → 提交申请 → 管理端批准
  → 手机授予通知访问权限 → 选择应用并保存
  → 解释后台同步及状态通知权限 → 用户明确开始同步，或选择稍后设置
  → 管理端生成 Chrome 加入码
  → 扩展填写服务地址、加入码、申请名称 → 用户授予该站点权限
  → 提交申请 → 管理端批准
  → 手机「设置 → 接收设备」选择该浏览器并保存
  → 所选应用实际产生通知 → 浏览器收到通知 → 查看或操作
```

两端加入可以交换顺序。先加入的一端不能因为另一端还没加入而被判为连接故障。

首次设置可以退出后继续，不因重启要求重新使用已消费的加入码。名称是申请名称，最终以管理员批准后的权威名称为准。站点权限拒绝、加入码过期、等待批准和申请被拒绝是不同状态，不合并成「连接失败」。

完成设置与完成首次通知交付分开：仅凭本机连接正常，不显示「通知已送达浏览器」。没有真实交付证据时，使用「已连接服务，等待通知」，提示用户让已选应用产生一条通知。开发夹具不进入正式引导。

### B. 日常查看和操作

```text
手机捕获符合策略的通知 → 浏览器系统通知／Popup 列表
  → 查看详情 → 普通操作、回复或从手机清除
  → 等待手机结果 → 显示完成、失效、失败或结果无法确认
```

每张通知卡片保留来源手机和应用。回复不因关闭 Popup 而显示为取消，也不能因为重新打开而自动再发一次。较长输入引导用户在独立交互窗口继续，窗口与工具栏 Popup 复用同一业务状态。

### C. 改变同步范围

```text
Android「应用」→ 搜索／筛选 → 勾选应用 → 显式保存
  → 进入应用详情设置正文、通知类型和操作权限
  → 提交成功后显示生效结果，失败不保留虚假的已保存状态
```

保存空选择是合法状态，提示「未选择应用，不会发送新通知」，不反复强迫用户回到引导。取消选择后按既有策略刷新机制清理对应镜像，不能仅隐藏应用行。

浏览器「筛选当前列表」与「在此浏览器隐藏某来源」分开。前者只改变查看范围，后者是持久展示偏好，两者都不改变 Android 的发送策略。

### 选择接收设备（新增）

用户已确认需要决定通知发往哪些设备，而不是固定发给全部成员。先按每台 Android 一组接收设备设计，应用选择决定「发什么」，接收设备决定「发给谁」。暂不扩展逐应用不同目标的规则矩阵。

入口为「设置 → 接收设备」，首页展示已选择的数量并直达同一页面。列表展示已获管理员批准且具备接收资格的浏览器，使用权威设备名称，不用实时在线状态决定是否可以选择。两台手机可以有不同的接收范围。

选择显式保存，空选择合法，保存后停止向任何浏览器发送新的通知。新配置和没有显式选择记录的旧配置默认空选择；旧版本已有用户保存的选择则原样保留，包括显式保存的空选择。旧版隐式向全部已批准浏览器发送不算显式选择。新批准设备不自动加入，实际发送范围始终取保存选择与当前有效接收成员的交集。

保存生效后，未选设备不应获得新产生的通知内容，也不得继续对本手机发起新的通知操作。实现需统一约束实时发送、启动快照、离线补发与新操作授权，不是浏览器端收到后隐藏。重新选中设备时，只同步当前仍有效且符合策略的通知，不提供历史归档。

取消选择不是撤销工作区成员资格，也不保证撤回已经发送、已经进入服务端队列或已经被对方保存的内容。此类内容可能在取消后才送达。尚未提交的本地发送工作必须按新范围重新检查；在途操作结果的收敛、已有镜像的残留提示与后续清理需在实现中明确，不能用一次 UI 勾选宣称远端已清空。设备丢失或不可信仍应由管理员撤销访问。

### D. 暂停和恢复

建议正式产品提供「暂停同步／恢复同步」，而不是要求用户理解 Activity 与前台服务的连接所有权。

这是一项功能调整，不是文案替换。目标语义是暂停后不再发送新的通知、不接受新的远程操作，恢复后按当前权限和应用选择对账。暂停前已经执行的操作不能撤回，在途操作不能伪装成已取消。具体队列和快照处理需在对应切片实现并验证。

该语义已在 Android 实现，后台连接开关仍只管理退出应用后的连接 owner，与业务暂停保持独立。暂停状态持久化，网络重连不能擅自解除；恢复后按当前应用和接收设备范围发送快照对账。

### E. 异常与重新加入

临时断网保留当前内容，并标注状态可能不是最新，不清空列表伪装成「没有通知」。权限缺失引导到相应系统设置；撤销或身份错误停止正常业务，并给出管理员处理路径。

更换服务和重新加入放在设置的危险操作区，说明旧访问、本地内容和待确认操作的影响。当前恢复能力不等于任意离线迁移能力：如果旧服务不可达，不承诺网页一键安全撤销或无损迁移。本轮不新增绕过身份校验的重置捷径。

## 4. Android 页面结构

### 建议导航：同步、应用、设置

把低频的只读「设备」放入设置，首页仍可直接进入设备列表。相比沿用四个一级入口，这样更突出「现在怎样」和「同步什么」。若后续设备本身出现高频可操作任务，再讨论提升层级。

```text
首次设置（主导航外）
  连接服务 → 等待批准 → 通知访问 → 选择应用 → 后台同步

同步
  主状态、原因与一个首要动作
  已选应用数量 → 应用
  已选择接收设备摘要 → 设置中的接收设备
  次要问题 → 详情／系统设置

应用
  搜索、已选／全部、普通／系统筛选
  应用列表：图标、名称、包名、选择状态
  批量选择、未保存提醒、保存
  应用设置快捷入口 → 设置中的对应应用页面

设置
  接收设备：本手机的目标浏览器、显式保存、空选择状态
  同步与后台：后台运行等配置
  同步默认设置：内容范围、通知类型、操作权限
  单个应用设置：正文与通知类型、继承默认／只查看／允许全部／自定义操作权限
  服务与设备：当前服务、当前设备、工作区设备列表
  权限与运行条件：当前状态、用途、缺失影响、授权／系统设置入口
  数据与隐私、重新加入
  外观与语言、关于
```

现有配置开关统一收纳到设置，包括全局默认、后台配置及单个应用的策略覆盖。首页只展示状态、问题入口和暂停／恢复这类直接动作，不重复放置配置开关。日常状态以文本和标准 Material 3 组件为主，不做仪表盘分数、心跳动画或虚构的同步成功计数。

应用一级页专注于识别和选择同步对象。每行显示应用图标、名称、包名及选择状态：图标帮助快速辨认，名称作为主文本，包名作为可读的次级文本，帮助区分同名应用。搜索同时匹配名称和包名。图标取自本机应用信息，获取失败时使用统一占位图标，不联网补取。长包名需能查看完整内容，不能只保留无法辨认的截断文本。

应用策略页面归属设置，应用列表可提供直达对应页面的入口，不复制另一套设置。明确展示「继承默认」及实际生效值，避免默认设置改变后用户仍误以为应用有独立覆盖。

应用选择沿用显式保存。应用策略设置建议统一采用保存式提交，离开未保存页面时可继续编辑或放弃。立即生效的暂停动作独立处理，不夹在草稿设置里。

### 权限与运行条件

设置中提供常驻的独立页面，不只在首次引导或权限缺失时出现。每项说明用途、当前状态、缺失影响，并提供系统实际支持的操作入口。

- **通知访问：** 查看是否允许读取所选应用的通知，缺失时进入对应系统授权页面。
- **状态通知权限：** 按 Android 版本展示真实状态，支持时发起权限申请，不能再次弹出申请时引导到应用通知设置。说明其与本项目后台同步的关系，不宣称所有 Android 应用都必须有该权限才能运行前台服务。
- **后台运行条件：** 展示系统能够可靠查询的电池限制等状态，区分必要权限与可选运行建议。不把电池优化豁免列为通用强制条件，也不猜测 OEM 专有开关已开启。

进入页面、应用回到前台以及从系统设置返回时重新查询实际状态，不把点击授权按钮当成授权成功。权限后来被撤销，首页提供直达本页对应问题的入口，用户也始终可以从设置主动进入。普通安装权限等不可由用户重新申请的项目不制作虚假的授权开关。

```text
设置 → 权限与运行条件

通知访问                         未开启
用于读取你选择的应用通知
[前往授权]

状态通知                         已允许
用于显示后台同步状态
[查看系统设置]

后台运行
显示当前可确认的限制与适用建议
```

以上状态是布局示例，不是当前设备的实测结果。

## 5. 浏览器扩展页面结构

### Popup：当前通知优先

```text
SevenMirror                            设置
连接异常时显示简短提示和处理入口

全部来源 ▾                         当前 8 条

手机名称 · 应用名称                  时间
标题
正文摘要
展开详情                               >
```

连接正常时不让连接说明占据大块区域。通知列表使用清晰分隔和紧凑间距，不把每条通知做成占满弹窗的大卡片。展开详情使用同一弹窗内的详情视图，保留返回位置。

详情包含全部可用操作、回复输入和明确的「从手机清除」。危险动作与「关闭详情」分离，不能用一个含糊的叉号同时承担两种含义。系统通知的按钮数量和输入能力受浏览器限制，完整处理能力放在详情中。

未查看角标沿用既有语义：只有用户点开详情查看过的通知才标记已查看，仅浏览 Popup 列表不标记，重连重复投递不制造新通知。不在本轮新增通知历史、归档或逐条本地丢弃模式。

### Options：真正的页面切换

- **连接与设备：** 当前服务、加入流程、权限状态、只读设备列表和重新加入
- **通知显示：** 系统通知、正文、图像、静默、角标和来源展示偏好
- **快捷操作：** 复用现有规则能力，由通知显示页进入二级页面
- **数据与隐私：** 本机内容说明和清理，明确不等于撤销设备或清除手机通知
- **关于：** 版本、许可证、文档

Options 已实现侧栏切换独立内容区，窄屏使用可横向滚动的导航，不再以锚点跳转一个长页面。连接错误继续使用既有状态给出精确处理入口，而不是把所有错误都导向重新注册。

点击 Chrome 系统通知主体已实现为 `440 × 680` 的独立小型交互窗口，不在普通浏览器窗口新增标签页。使用 `chrome.windows.create({ type: 'popup', ... })` 承载现有 Interaction 页面，窗口保留系统标题栏及关闭控件，不显示普通浏览器标签栏。

此窗口与工具栏 Popup 不同，失焦不会自动关闭，适合查看完整正文和输入回复。关闭窗口只关闭详情，不清除手机通知；清除仍由明确操作发起。Popup 与 Interaction 不维护两套操作、版本检查或结果状态。

`service-worker.ts` 的 `openNotificationInteraction` 已改用独立窗口，并继续复用现有详情、revision、操作和回复逻辑。低保真原型中的详情区仍只表达内容布局，不是生产窗口的验收证据。

## 6. 服务端管理页面结构

服务端管理界面已将设备任务作为首页，没有新增空洞的概览仪表盘。界面按左侧分类导航加右侧面板组织：导航项是普通链接，选中分类由服务端路由 `/?section=<分类>` 决定，页面里没有可用于切换的脚本。登录后默认落在设备分类，先显示待处理申请，再显示已接入设备详情；已拒绝或移除设备默认折叠。

```text
SevenMirror 管理端                                        退出
设备 │ 凭据 │ 设置 │ 部署与维护 │ 关于
────────────────────────────────────────────────────────────
（右侧是所选分类的面板，下例是设备分类）

私有空间                              [添加设备]
创建于 2027-01-12 08:00:00 +00:00
Android 1   Chrome 1   待处理 1
待处理申请（优先显示）
  申请名称、类型、申请时间 → 批准／拒绝

已接入设备
  名称、类型、最近活动 → 详情

已撤销／已拒绝（默认折叠）
```

- **分类导航：** 设备、凭据、设置、部署与维护、关于五项，管理操作成功后回到发起操作的那个分类
- **私有空间：** 只有一个，不显示编号，也不提供改名，页面不建立多账号或多工作区概念，因此只显示创建时间
- **添加设备：** 选择类型 → 生成并一次性展示加入码 → 指引客户端申请 → 查看待处理申请
- **设备详情：** 名称、类型、成员状态、申请／批准／最近活动时间，重命名和撤销
- **危险确认：** 明确对象名称和后果，撤销不是直接删除数据库记录
- **设置：** 只改当前浏览器的时间显示时区，服务端记录、设备状态和同步行为都不受影响
- **部署与维护：** 管理端访问方式、版本和可验证状态、Docker 与备份恢复指引
- **关于：** 许可证、文档、诊断说明

时间戳按 `2006-01-02 15:04:05 -07:00` 打印偏移量，默认 UTC；改时区只改可读性，不改时刻本身。设备条目使用「最近活动于……」，不把采样时间转换为严格在线标记。管理端网页可访问也不能证明公开中继健康。

部署初始化、恢复、authority 密钥维护继续由本机工具完成。若没有可信备份记录，只显示「未取得备份状态」和操作指引，不能显示推测的「备份正常」。是否接入只读健康／备份摘要，取决于已有可靠数据来源，不为填满页面建设一套监控系统。

## 7. 状态和反馈

三端共享事实含义，不强迫使用相同的大标题。页面从现有业务状态派生展示，不建立第二套连接或通知数据库。

| 情况 | 用户反馈 | 首要动作／约束 |
|---|---|---|
| 尚未加入 | 连接你的私有服务 | 开始设置 |
| 申请已提交 | 等待管理员批准 | 查看申请状态，不重复消费加入码 |
| 连接已建立 | 已连接服务 | 不等于对端已收到通知 |
| 没有接收成员 | 尚未添加浏览器 | 查看添加设备说明，不标为网络故障 |
| 已授权但未选择接收设备 | 未选择接收设备 | 进入设置选择，允许保留空选择 |
| 已选择接收设备 | 已选择若干接收设备 | 不推断对端实时在线，新成员不自动加入 |
| 空应用选择 | 未选择同步应用 | 选择应用，可保留空选择 |
| 用户暂停 | 同步已暂停 | 恢复，不自动重连并恢复业务 |
| 临时断网 | 连接中断，正在重试 | 保留内容，提示可能不是最新 |
| 权限缺失 | 需要通知访问／状态通知权限 | 分别引导，不统称未授权 |
| 访问被撤销 | 此设备的访问已被移除 | 管理员处理后重新加入 |
| 身份验证异常 | 无法安全连接 | 停止业务，提供恢复指引，不提供忽略验证 |
| 操作在途 | 正在等待手机结果 | 避免再次提交 |
| 通知已更新或移除 | 此操作已失效 | 查看当前通知 |
| 操作结果不确定 | 无法确认是否已执行 | 提示检查手机，不显示成功、不自动重发 |

有多个问题时，先展示阻止安全使用的问题，再是成员资格、权限、用户暂停、连接与同步范围问题。其他问题可展开查看，不堆叠多个争抢注意力的横幅。

## 8. 视觉与交互方向

建议采用「克制的系统工具」方向，而不是开发控制台或数据大屏。三端统一品牌标识、术语、状态语义和图标含义，布局遵循各平台习惯。

- Android 使用 Jetpack Compose 和实施时稳定版 Material Design 3，支持动态颜色、深色模式、edge-to-edge 与自适应导航
- Web 使用中性底色、少量品牌强调色、明确分区和可见焦点，不强行复制手机底部导航
- Web 优先保留现有 HTML／CSS／TypeScript 与 Go 模板，不为换视觉引入大型框架
- 颜色、排版、间距、形状在各端集中定义，跨端共享语义，不机械共享像素值
- Android 触控目标至少 48 dp，Web 支持键盘、屏幕阅读器和 200% 缩放，错误不只靠颜色表达
- Android 与扩展沿用中英文资源，管理端需补齐英文与可维护的文案资源机制
- 开发诊断与测试入口从正式导航中移除，不把协议枚举翻译后直接展示

本轮不指定未经确认的品牌色、字体或最终组件尺寸。方向确认后先给出首页、应用详情、Popup／通知详情和管理设备页的低保真布局，再落实设计系统与交互状态，不直接沿旧页面换色。

## 10. 实施顺序与验收

### R1：确认方向与关键页面

确认导航、暂停语义和视觉方向。随后形成低保真页面及加载、空、失败、恢复状态。批准草案不等于每个视觉细节已经定稿。

### R2：加入设备并开始同步

Android 首次设置与同步页、扩展加入页、管理端添加和审批页组成一个切片。独立主题分支分别落地，保留旧业务层与已有配对数据，不要求老用户清数据。

验收：全新环境按指引完成加入，不暴露协议术语；等待批准可跨重启恢复；权限拒绝可以继续处理；实际收到一条所选应用的通知，不能拿连接成功替代交付。

### R3：控制范围并处理通知

Android 应用列表、设置中的应用策略、权限与运行条件页面及暂停，扩展列表、详情、回复和快捷操作，再补齐其余设置页与管理设备详情。

验收：未保存更改不生效；拒绝操作的策略不能被浏览器绕过；暂停后无新业务副作用；相同应用来自不同手机时操作仍精确返回来源；通知更新、失效和结果不确定时反馈正确。

### R4：完整体验与交付验收

完成深色模式、字体缩放、键盘、横屏、窄屏、语言及升级数据兼容；集中修复网络恢复并继续未完成的实机与发布验收，落实便捷 Docker 交付。TalkBack 按用户 2026-09-15 的决定移出近期验收范围，保留为后续独立质量项，见 `DEVELOPMENT_PLAN.md` 第 7 节。

实现按主题分支、精确 SHA 必需 CI、快进主线与清理的既有流程执行。本轮只有根目录规划文档，不创建三个仓库的空分支或无关 CI。

## 11. 请用户确认的三个取舍

1. **Android 主导航采用「同步／应用／设置」三项，把只读设备列表降为二级入口。** 推荐此方案，因为设备管理只能在服务端完成，手机的高频任务是同步状态和应用范围。
2. **将「暂停／恢复同步」纳入本次功能调整。** 推荐做真正的业务暂停，首次设置明确说明并由用户开始后台同步，不把旧开关改名冒充实现。
3. **采用原生、克制的工具型视觉。** Android 遵循 Material 3，Web 保持紧凑清晰，统一品牌语义但不强制三端长得一样。

用户已认可大方向，并明确要求配置开关收纳到设置、应用列表显示图标和包名、设置提供独立权限页面及重新授权入口。上述补充已纳入本稿及低保真原型，用户已认可低保真布局大体方向，并新增按手机选择接收设备的要求，原型与业务调整清单已补充。具体细节继续评审，不默认继续底层接管，也不提前改生产界面代码。
