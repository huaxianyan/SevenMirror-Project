# Chrome Web Store 隐私字段填写说明

适用版本：SevenMirror Extension `v0.1.22`。
本文用于填写开发者后台的「隐私权规范」字段，不替代面向用户的隐私政策。
提交前应确认表单、公开隐私政策和实际运营行为一致。

## 单一用途说明

可填写：

> 将用户选择的 Android 手机通知同步到用户选择的浏览器，在电脑上查看通知详情，并执行原通知提供的操作或回复。同步范围由手机侧选择的应用和接收设备控制，用户通过自己指定的 SevenMirror 服务完成配对和传输。

通知展示、回复、快捷操作和接收设备选择都围绕同一目的：在电脑继续处理手机通知。

## 权限用途理由

### `notifications`

> 在电脑显示手机同步过来的系统通知，并更新或清除对应通知。用户点击通知后，可以查看详情并执行原通知提供的操作或回复。这是扩展的核心用户功能。

### `storage`

> 使用 chrome.storage.local 保存通知展示偏好、快捷操作规则、接收来源选择、连接状态，以及通知按钮与可用操作的对应关系，使设置和操作状态可以在浏览器重启后恢复。

此权限理由仅针对 `chrome.storage` 的用途，IndexedDB 本身不依赖该权限。
连接凭据、身份密钥和通知内容还使用扩展自己的 IndexedDB 存储。
部分本地记录包含明文，不能把「扩展本地存储」写成「全部加密存储」。

### `alarms`

> 定时重试断开的服务连接、刷新设备授权状态，并重试通知恢复和操作确认。启用跨浏览器规则同步时，也用于定期获取规则更新，使浏览器后台暂停后能够继续恢复同步。

### `system.display`

> 读取显示器的工作区尺寸，将独立通知交互窗口放到可见的屏幕区域，避免窗口出生在错误位置或被系统通知遮挡。该权限用于窗口定位，不用于截屏或采集屏幕内容。

### `offscreen`

> 在扩展界面关闭时播放随扩展打包的通知提示音。页面仅用于音频播放，遵循用户的静默设置，不读取网页或屏幕内容。

音频随 ZIP 分发，不从远程服务加载，也不新增用户数据类别。
主动点击「试听提示音」时，即使静默开启也会播放。

### 主机权限

表单若将多个主机权限分开列出，分别填写对应用途。

`https://*/*`：

> 用户可以连接不同域名上的自托管 SevenMirror 服务，因此声明可选的 HTTPS 主机范围。实际配对时，只请求用户填写的服务 origin，供扩展与该服务交换配对、授权、加密通知、操作结果和加密快捷规则数据。该权限不用于读取用户正在浏览的网站或采集浏览历史。

`http://localhost/*`、`http://127.0.0.1/*` 和 `http://[::1]/*`：

> 支持用户在本机运行 SevenMirror 服务时连接回环地址。HTTP 例外仅限本机回环服务；普通远程服务使用 HTTPS。实际授权仍按用户填写的服务 origin 请求。

不要把声明的 `https://*/*` 写成运行时已授权所有网站。
也不要把回环地址例外写成「所有连接均为 HTTPS」。

## 远程代码声明

当前版本选择：**否，不使用远程代码**。

可填写：

> 扩展的可执行 JavaScript 和依赖随提交 ZIP 一起打包。服务端提供配对、授权和加密业务数据，不提供需要在扩展中下载并执行的 JavaScript。快捷操作规则是由本地代码解释的数据配置，不是远程脚本。

这项声明针对可执行代码，连接自托管服务本身不等于使用远程代码。

## 用户数据类别

**不能选择「不收集或不使用任何用户数据」。**
Chrome 的数据处理定义包含本地处理和保存，不只包括上传给开发者。

建议至少披露以下类别：

| 类别 | 实际处理内容 |
| --- | --- |
| 个人身份信息 | 用户填写的设备显示名称，以及通知中可能出现的联系人姓名、地址或账号等信息 |
| 身份验证信息 | 配对输入、连接凭据、设备身份密钥和规则同步的加密配置 |
| 个人通讯 | 通知标题、正文、附件展示信息，以及用户输入的回复 |

通知来源由用户选择，当前版本不按正文中的敏感内容类别筛除通知。
因此，若提供任意应用通知同步，应同时考虑并如实披露以下类别：

| 类别 | 可能进入同步通知的内容 |
| --- | --- |
| 健康信息 | 医疗、健康或运动应用的通知内容 |
| 财务和支付信息 | 支付、订单、银行或交易应用的通知内容 |
| 位置信息 | 地点、行程、配送地址或位置应用的通知内容 |

本扩展没有通过地理定位 API 主动采集位置，但通知内容可能包含位置。
「没有调用定位 API」不能替代对实际处理内容的披露。

本扩展不读取浏览器网页 DOM、浏览历史或其他网站的 Cookie，也不监测用户在网页上的键盘和鼠标活动。
不要仅因声明了可选主机权限，就描述为浏览历史或网页采集工具。
若你修改功能或加入统计服务，应重新评估类别，而不是继续沿用本文。

## 数据使用说明

可作为表单补充说明：

> 扩展只为通知同步、呈现、操作、回复和用户启用的规则共享处理数据。通知与操作内容在发送端加密，在获准的接收端解密；规则共享也上传加密数据。服务连接及授权需要交换设备和工作区标识等元数据。浏览器端会保存必要的身份、通知和操作状态，通知内容会在用户自己的浏览器中解密并呈现。

发布者应逐项确认商店中的数据使用认证声明。
当前功能不需要出售用户数据、定向广告、无关分析或信用与贷款资格判断。
填写后，实际运营也必须遵守这些限制；若另行部署统计或日志服务，需相应披露。

不要承诺「服务器收不到任何信息」。
中继服务会处理连接凭据、设备标识、路由与投递状态等必要数据，运营者也可能拥有连接日志。
端到端加密的范围是业务内容，不是全部网络元数据。

## 本地保留与删除说明

公开隐私政策需要如实交代：

- 本地保存解密后的通知展示内容，包含标题、正文和必要的图片信息
- 待处理操作可能保存回复内容，过期记录在后续存储活动中清理，当前期限为 30 天
- 通知移除后仍可能保留用于版本对账的历史记录，当前没有独立的产品级历史清理入口
- 暂停同步或撤销访问停止后续使用，不等于历史数据已全部删除
- 卸载扩展或删除浏览器配置是当前广泛的本地删除方式，浏览器备份和系统历史仍需单独考虑

不要把待处理操作的 30 天期限扩大成「全部通知数据只保留 30 天」。

## 提交前的待处理事项

### 公开隐私政策 URL

需要提供面向用户、可公开访问的隐私政策。
本文是填写说明，不能直接冒充完整隐私政策。
政策至少应覆盖数据类型、用途、共享、保留、删除、安全措施和联系渠道。

### 静态数据加密与保留风险

当前部分通知、回复和连接凭据以可恢复的明文保存在浏览器本地。
非导出的身份密钥不等于所有本地业务数据都已加密。
Chrome 官方 FAQ 对静态数据加密提出要求，这一风险需要在送审前处理或明确向审核方说明。

本说明不承诺已经满足全部商店要求，也不能保证审核通过。
独立安全评审尚未完成的状态不因提交商店资料而改变。
