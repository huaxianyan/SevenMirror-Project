# 仓库内容边界

本仓库是 SevenMirror 的项目总仓库。放什么、不放什么，按下面的边界执行。

## 放这里

- 整套系统的说明：三个组件怎么协作、信任关系从哪来、服务端看得见什么。
- 产品与规格文档：需求、信息架构、重设计方向。
- 计划与留痕：阶段计划、逐轮执行进展、交付记录。
- 设计原型：低保真界面参照。
- 许可证与切换说明。

## 不放这里

- **可执行代码**。服务端、扩展、Android 各自的源码、构建配置、CI 与依赖锁都在对应仓库，本仓库不做镜像或搬运。
- **内网与主机细节**。内网地址、主机名、工作机名、服务器绝对路径、设备序列号、远程调试端口一律不写。需要指向这些信息时写「见本地约定文件」。
- **凭据**。口令、令牌、密钥、证书内容、私钥路径都不写。要说明凭据放在哪，只写位置类型，不写具体值。
- **证据目录**。开发机上的 `.tools/` 是临时证据与脚本的存放处，体量大且含设备转储、调试日志与一次性脚本，属于草稿而不是留痕依据，不上传。留痕文档里引用 `.tools/<主题>/` 的地方，表示该轮的原始证据在开发机上，不在本仓库。
- **助手私有目录**。`.claude/`、`.pi/`、`.workbuddy/` 这类目录不做留痕载体，换了工具就没人看得到。

## 与三个组件仓库的分工

| 内容 | 放哪 |
| --- | --- |
| 源码、构建、CI、依赖锁 | 对应组件仓库 |
| 组件自己的技术文档（协议、部署、安全审查） | 对应组件仓库的 `docs/` |
| 组件自己的 README 与许可证 | 对应组件仓库 |
| 跨组件的系统说明 | 本仓库 |
| 产品需求与设计 | 本仓库 |
| 阶段计划与逐轮交付留痕 | 本仓库 |

组件仓库里指向本仓库的链接，一律用绝对 URL，不用相对路径，避免两边目录结构变化后链接失效。

## 写留痕时的注意事项

- 写清事实与来源，不写没有核实的推测。
- 涉及主机与设备时用占位符或组件类型描述（例如「测试主机」「Pixel 真机」），不写具体主机名与序列号。
- 不写自有域名的二级标签。它不止出现在 origin 里，还可能藏在公开包名中（例如 `com.<二级标签>.sevenmirror`）⇒ 脱敏正则若按标签匹配，会误伤包名这类不能改的技术事实。域名要么写完整主机名，要么不写。
- 提交信息与文档里不出现凭据明文。
- 记录里的提交 SHA 与部署状态是当时的快照，读的时候要重新核对。
- 脱敏同步之后必须抽查两件事：公开包名、仓库名、提交 SHA 有没有被误改，以及被替换处前后的断句是否完整。
