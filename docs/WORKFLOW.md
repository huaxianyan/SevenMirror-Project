# 协作流程

分支收尾、测试节奏、测试进程与文案记录四件事的约定。

## 分支收尾与检索卫生

- 总仓库 `SevenMirror-Project` 的 `privacy-pages` 分支是用户要求的 GitHub Pages 长期部署源，根目录 `index.html` 是双语隐私政策的唯一正文来源。它不是待合入的开发主题分支，不合入 `main`，也不按已验收主题分支流程删除；主线只维护产品详情、部署链接和交付记录。用户已选择并手动配置 GitHub Pages，分支为 `privacy-pages`、目录为根目录；正式 URL 为 `https://huaxianyan.github.io/SevenMirror-Project/`。部署配置与最新提交的线上生效状态须分别核实。

- 用户最新要求：当前开发不走 PR，使用独立主题分支承载开发改动；验收及必需 CI 检查通过后必须合入对应仓库的 `main`，不得把已验收成果长期留在分支上。这一要求替代此前默认通过 PR 合入的约定。
- 经用户确认，三个仓库 GitHub ruleset 已仅移除 `pull_request` 规则，仍保留必需状态检查、禁止主线删除和禁止非快进推送。Android 必需检查为 `build`、`api29-secure-runtime`，Extension 和 Server 为 `test`，不通过管理员豁免绕过这些门禁。
- 在主题分支上完成验收和必需 CI，优先将已验证的分支头快进合入 `main`，避免生成未经检查的新合并提交。若为跟进主线而改变分支头提交，应验证新的提交，不能复用旧 SHA 的检查结果。
- 三个仓库的 CI 均已覆盖所有分支的 push，保留原有检查内容及 PR／手动触发入口，但当前开发不创建 PR。无 PR 流程由主题分支 push 触发必需 CI。不能只凭手动 `workflow_dispatch` 的绿灯认定远端合入门禁已满足；若 GitHub 拒绝，核对真实 check 与规则评估，不手动补写成功状态、不新增空放行任务，也不绕过保护。
- 合入后确认主线 CI 结果，返回并同步本地 `main`，核实没有独有改动后清理本地及远端主题分支与过期远端跟踪引用，作为该轮交付的正常收尾。
- 用户明确要求审计并控制已验收分支的残留，避免增加后续代码检索成本。已完成的主题分支不能作为默认的长期归档方式，历史依据使用 PR 和提交记录。
- 清理前核对本地改动、worktree、stash、实际远端、PR 状态和分支独有提交。squash 合并不能只依赖 `git branch --merged`，需补充 PR head、主线合并提交与内容一致性证据。
- 按用户确认的范围清理分支和修改仓库设置；未完成或存在独有工作的分支必须说明保留理由。删除远端分支时防止覆盖审计后新增的提交，不修改主线保护、标签或 Git 全局配置。
- 三个 GitHub 仓库此前已开启 PR 合并后自动删除远端主题分支，三个仓库本地均已设置 `fetch.prune=true`。当前不走 PR 的流程不能依赖该自动删除设置，验收合入后须主动清理本地和远端主题分支。
- 分支审计不能替代逐模块代码审查、安全审计或功能验收。历史文档与当前操作指南应区分，发现主线指南仍描述已退役流程时单独报告和修订。

## 测试节奏

- 用户要求尽快达成三端真实可用，减少单元测试的编写频率。不再默认「每个改动配一份单元测试」；纯视觉、文案与导航结构调整以构建通过和真机可见验收为准。
- 验证重心是统一的现有测试集：本地一次跑完 `verifyKotlinKaptAdvisoryGuard`、单元测试、lint、APK 与 androidTest 编译，再接必需 CI，不在开发过程中反复插入小范围定向测试。
- 既有的安全、密码学、协议与持久化边界测试是既有资产，保持不变，不得以提速为由删除、跳过或降级。
- 加速方式是减少新增测试的数量与频率，不是降低门禁。三个仓库的必需检查与真机验收仍是合入前提。
- 视觉层改动（动画、间距、颜色）不为每个改动新增测试，用真机录屏或截图作为验收依据。

## 测试进程

- 本地测试服务、代理和其他长时间运行的测试进程必须以无窗口后台方式启动，不得弹出或保留控制台窗口。
- 验收或调试完成后主动停止不再使用的测试进程并确认监听端口已释放。确需跨轮保留时，必须在交付说明中明确进程用途、监听地址和停止方式。
- **测试收尾必须把痕迹清干净。** 临时数据统一下在工作区根目录 `.smoke-tmp/`，收尾时整个删除，不留 profile、脚本、扩展副本。浏览器类验收还要额外做两件事：清掉已经弹到桌面上的镜像通知（扩展的镜像通知带 `requireInteraction: true`，不会自己消失，先清通知再关进程，顺序不能反），以及复原设备与偏好到实验前并核对 md5。逐项清单见用户级技能 `sevenmirror-chrome-extension-verify` 的「收尾」。
- **用户的日常浏览器不是测试资源。** 不要结束它的进程，也不要改它的配置文件。区分实例只看命令行 —— 带调试端口或 `--user-data-dir` 指向测试目录的才是测试实例；「调试端口已释放但还有同名进程」不能作为判定残留的依据。需要改动用户浏览器里的东西时，交给他自己在界面里操作。

## 文案、记录与交接

- 简体中文文案遵循用户级技能 `chinese-tech-writing`：默认直角引号 `「」`，中文与英文、数字、行内代码、超链接之间加一个半角空格，全角标点，单句不超过 100 字。**这替代此前「本项目历史文档用全角弯引号」的印象**；`docs/STATUS.md` 残留的 13 对弯引号已于 2026-09-29 统一为直角引号，此后新写内容一律用直角引号。
- 排版门禁随已安装的 `chinese-tech-writing` 技能提供，`check_typography.py`（另有 `check_style.py` 与 `check_clauses.py`，随技能安装，本机具体路径见 `AGENTS.md`）。**它适用于新写或重写的文档，不对历史档案批量改写**：2026-09-29 实测 `docs/` 与三端 README 共 934 条命中，其中 878 条是更早历史档案的列表项末尾分号，该判据按技能说明只针对 README 与发布说明 ⇒ 拿它去改历史档案属误用。
- **进度记录写在仓库里、随代码提交**。2026-09-29 起分两处：跨组件留痕（系统说明、产品文档、计划与逐轮交付记录）在总仓库 `SevenMirror-Project`（<https://github.com/huaxianyan/SevenMirror-Project>），组件自己的技术文档在各自仓库的 `docs/`。**不用 `.workbuddy/` 也不新建 `.pi/`、`.claude/` 一类助手私有目录作进度记录**——换了工具就没人看，做不到交接。`.workbuddy/memory/` 下已有的历史草稿已随归档整理删除，长期结论并进本文件与 `docs/`。
- **总仓库入库前必须脱敏**：它是公开仓库，不得出现内网地址、主机名、服务器绝对路径、设备序列号、远程调试端口与凭据。内容边界与占位符口径见总仓库 `docs/CONTENT_BOUNDARY.md`。本机 `.tools/` 是临时证据目录，不入库；留痕里引用 `.tools/<主题>/` 只表示原始证据在开发机上。
- 把留痕同步到总仓库时，用本机脚本 `.tools/conventions-audit/sanitize_copy.py`（源文件只读、目标另写、逐条统计命中数）。**2026-10-29 核对：该脚本在本机已不存在（旧工作区删除时一并丢失），需要时按本节口径重写，不要假定它还在。**
- 脱敏脚本只换主机与设备细节，绝不改公开的包名、仓库名、提交 SHA 与协议标识——上一版正则曾把 `com.neko7ina.sevenmirror` 误写成占位符，改完必须抽查。
- 接手一个项目前按 `project-conventions` 的交接清单核对现场：仓库、分支、`git status`、`git log -1`、CI 结果、部署实跑镜像、外部服务可用性。**记录里的 SHA 与部署状态是当时的快照，不能直接沿用**。2026-09-29 的实例：`docs/DEVELOPMENT_PLAN.md` 1.1 把 SR-015 的文案矛盾列为待修，实际早已被 `2d0d623` 超越 ⇒ 过期待办就地作废，不重复开工。
- 开工前说清预期：这一步做什么、大概多久、超时怎么办。分钟级命令显式设超时；连续两次失败就停下来报告，不试第三次。
